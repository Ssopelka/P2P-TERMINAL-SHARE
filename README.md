# P2P TERMINAL SHARE

## 1. Как работает новый режим P2P (WebRTC)

В проекте теперь два независимых режима, переключатель — на главной странице:

- **Реле** — файл шифруется AES-256-GCM и целиком загружается
  на сервер, получатель скачивает и расшифровывает его в браузере. Сервер
  видит зашифрованные байты и хранит их до истечения TTL/лимита скачиваний.

- **P2P** — файл вообще не попадает на сервер. Сервер участвует
  только в *сигнализации*: помогает двум браузерам договориться и обменяться
  SDP/ICE через WebSocket (`/ws/signal/{room_id}`). Как только
  `RTCPeerConnection` установлен, данные идут напрямую между браузерами по
  `RTCDataChannel`, зашифрованные протоколом DTLS (это встроено в WebRTC,
  дополнительный AES не нужен).

### Файлы, которые это реализуют
- `main.py` — эндпоинт `POST /api/p2p/create` (создать комнату) и
  `WS /ws/signal/{room_id}?role=sender|receiver` (чистый релей сообщений,
  без сохранения файлов).
- `static/js/webrtc-common.js` — общие константы (STUN-серверы, размер чанка).
- `static/js/webrtc-sender.js` — класс `P2PSender`: создаёт offer, каналы
  `control` (JSON-метаданные) и `data` (бинарные чанки), учитывает
  backpressure (`bufferedAmount`), шлёт файлы из очереди по одному.
- `static/js/webrtc-receiver.js` — класс `P2PReceiver`: отвечает на offer,
  принимает чанки. Если браузер поддерживает File System Access API
  (`showSaveFilePicker` — Chrome/Edge), пишет сразу на диск потоково —
  можно передавать файлы любого размера. Иначе копит `Blob` в памяти
  (ограничение — оперативная память браузера) и отдаёт как обычную ссылку-скачивание.
- `static/p2p.html` — страница получателя (`/p2p/{room_id}`).
- `static/index.html` — переключатель режима и логика отправки.

## 2. Сборка в .exe
```bash
pip install -r requirements.txt
pip install pyinstaller
pyinstaller build.spec
```

Результат — `dist/p2p-share.exe` (на Windows) или `dist/p2p-share` (Linux/macOS,
там расширения `.exe` не будет, но бинарник будет исполняемым для этой ОС —
кросс-компиляция PyInstaller не поддерживает, .exe для Windows нужно собирать
именно на Windows или в Windows-контейнере/VM).

Если нужен файл без консольного окна — в `build.spec` смените `console=True`
на `False`, но тогда вы не увидите ни адрес, ни ошибки при старте (полезно
только когда всё уже отлажено).
